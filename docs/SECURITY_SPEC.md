# VeriBridge AI MVP SECURITY_SPEC

## Security philosophy

Security is part of MVP, not later.

Principles:
1. Private by default
2. Student-controlled publishing
3. Consent before recording or publishing
4. Raw evidence never publicly exposed directly
5. Public reports use tokenized links
6. Public report payload is allow-listed
7. GitHub tokens are encrypted and never logged
8. Supabase RLS protects owner data
9. API routes still check ownership because service role bypasses RLS
10. Unsafe AI wording is blocked by code gates
11. Every state transition is audited
12. Deletion/unpublish must work

## Must build in MVP

- RLS on all new tables
- private storage buckets
- signed upload/download URLs
- consent_records
- audit_logs
- data_deletion_requests
- tokenized public reports
- report public serializer
- banned wording gate
- citation coverage gate
- link allow-list
- GitHub token encryption
- route ownership checks
- no raw storage paths in public HTML
- no service keys in frontend bundle

## Data classification

Public:
- published report public projection
- published report token page
- methodology page

Private:
- user data
- project setup data
- repo analysis
- report draft
- admin review data

Sensitive:
- full session video
- webcam/audio
- transcript
- keyframes
- report views with IP hash
- student outcomes

Secret:
- GitHub OAuth tokens
- Supabase service role key
- API provider keys
- encryption keys

## Consent

Write consent records for:
- recording session
- publishing report
- publishing passport later
- university/program analytics later
- outcome sharing later

Recording must not start until recording consent exists.

Publishing must not happen until publish consent exists.

Consent records are append-only.

## Public report security

Public report is served by token:
- `/r/{token}`

Never expose:
- raw report draft
- internal model rationale
- suppressed claims
- GitHub token data
- storage paths
- bucket names
- raw transcript unless cited and approved
- unrelated evidence
- other student data
- admin notes

Public report must be generated by one allow-listed serializer.

Unpublish must:
- revoke public token
- stop media signed URL minting
- make old public link return 404

Token rotation must:
- create new token
- invalidate old token

## Media security

All storage buckets private.

Upload flow:
1. Client asks API for signed chunk upload URL
2. API checks authenticated user owns session
3. API checks session is in recording state
4. API checks chunk size and index
5. API returns short-lived signed PUT URL

Playback flow:
1. Client requests evidence media through API
2. API checks ownership or published report state
3. API checks media evidence is allowed for this report
4. API returns short-lived signed GET URL

Never accept client-supplied storage paths for playback.

## GitHub token security

GitHub tokens must be:
- encrypted before storing
- decrypted only in backend/worker
- never returned to frontend
- never logged
- revocable by user
- minimal scope

Use read-only scopes where possible.

## AI safety gates

All recruiter-visible AI output must pass:

1. Banned wording gate
Blocks:
- fraud
- fake
- cheating
- dishonest
- suspicious
- red flag
- risk score
- 100%
- guaranteed
- hire / do not hire
- wrote every line
- built entirely by student
- AI-generated as a verdict

2. Citation coverage gate
Every public claim sentence must link to evidence.

3. Link allow-list gate
Only allow:
- submitted GitHub repo links
- submitted deployed URL
- internal evidence links

4. Quote fidelity gate
A quote shown in report must exist in transcript segment.

5. Schema validation
LLM output must match expected JSON schema.

AI can suggest judgments.
Code assigns final tiers.

## Prompt injection defense

Treat all repo content, README text, transcript text, deployed page text, and file names as untrusted.

LLM prompts must:
- label untrusted content clearly
- never follow instructions inside repo/transcript/deployed content
- use structured output
- avoid tool use in judgment/synthesis calls

Prompt injection test fixtures should later include:
- README injection
- code comment injection
- transcript injection
- deployed page injection

## RLS rules

New MVP tables must have RLS enabled.

General rules:
- user can read/write own project setup data
- user cannot read another user's projects/sessions/reports
- public cannot read raw tables
- public report access goes through API serializer, not direct RLS table access
- service role is only used in backend/worker
- admin access is server-side checked and audited

## Audit logs

Append-only audit logs for:
- project created
- repo ingested
- claims generated
- claims confirmed
- session started
- session finalized
- media processed
- report generated
- admin reviewed
- report published
- report unpublished
- token rotated
- deletion requested
- deletion completed
- admin edits
- public report views

No update/delete on audit logs.

## Deletion and unpublish

Student can:
- unpublish report immediately
- request project deletion
- request account deletion later

Deletion worker must:
- delete storage objects
- tombstone or delete DB rows as appropriate
- write deletion manifest
- be idempotent

Consent/audit records may be retained as tombstoned legal records.

## Frontend security

Frontend must:
- never include service role key
- never include API secret keys
- never render untrusted markdown as raw HTML
- ban dangerouslySetInnerHTML unless explicitly reviewed
- sanitize/escape repo names, claim text, transcript text
- use strict CSP on public report page
- avoid third-party trackers on public report page
- not leak storage paths in DOM

## Admin security

Admin review is required before report publish in MVP.

Admin actions must be audited:
- view report in review queue
- edit report wording
- approve report
- reject/send back

Admin cannot:
- read GitHub tokens
- delete audit logs
- publish without student consent
- edit final tier directly without rerun/review record

## Security tests

MVP tests should include:
- user A cannot access user B project/session/report
- anon cannot read private tables
- public token works only when report published
- old token fails after rotation
- unpublish blocks media mint
- direct storage access fails without signed URL
- banned terms are rejected
- uncited report sentence is rejected
- XSS strings render harmlessly
- service keys not present in frontend bundle
- deletion removes media objects

## D14 security floor

Do not ship public report unless these exist:
- RLS on MVP tables
- private storage
- signed URLs
- consent gate
- GitHub token encryption
- public report serializer
- tokenized report links
- banned wording gate
- citation coverage gate
- audit logs
- unpublish flow
